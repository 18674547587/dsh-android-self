# 修复报告：Android 退出码 159（musl 版，build-23）

## 一、上一版为什么没修好

`159 = 128 + 31 = SIGSYS`。

上一版把 proot 里 glibc 的 `rseq(293)` 调用点改写成 `syscall(-1)`，理由是
"超范围的 syscall 号内核会返回 ENOSYS"。这在普通 Linux 上成立，但**在 Android 上不成立**。

AOSP 的 seccomp 生成器（`bionic/libc/seccomp/seccomp_policy.cpp`）里：

```c
inline void Disallow(filter& f) {
    f.push_back(BPF_STMT(BPF_RET|BPF_K, SECCOMP_RET_TRAP));   // → SIGSYS
}
```

**未列入白名单的 syscall 一律 TRAP**，不存在"超范围就放行"。`-1` 当 u32 是
`0xFFFFFFFF`，照样不匹配任何白名单条目，照样 SIGSYS。

实测两个包里的 `assets/proot/proot`：

| 包 | `movz x8,#293`（原样） | `movn x8,#0`（= -1） | 真机 |
|---|---|---|---|
| build-20 | 1 处 | 0 处 | 159 |
| build-22 | 0 处 | 1 处 | 159 |

CI 当时没发现，是因为 `tools/seccomp-kill2.c` 只对**指定的号**发 SIGSYS，
`-1` 不在列表里就被放行 —— 模拟 filter 没模拟到 Android 的真实行为。

## 二、这一版的做法

proot 不再用 glibc，改用 **zig + musl 静态编译**。

musl 的启动路径（qemu `-strace` 实测）：

```
set_tid_address / brk / mmap / getpid / ioctl / writev / exit_group
```

全部在 Android 10 的白名单里，**不碰 rseq，也不碰 clone3**。

rootfs 里的 glibc 程序（node 等）仍会调 `clone3/rseq`，这些由 proot 在
syscall-enter 阶段伪造成 `ENOSYS`，让 glibc 走回退路径（`scripts/patch-proot.py`）。

顺带把伪造用的"空 syscall"从 `io_setup(0)` 换成 `getpid(172)`：Android 的白名单
不一定有 `io_setup`，但一定有 `getpid`。

## 三、构建链

- `zig cc -target aarch64-linux-musl`：单文件 45MB，比 NDK（700MB+）轻得多
- `libtalloc.a`：直接取 Alpine 的 `talloc-static`（musl aarch64），省掉 waf 交叉编译
- loader 必须链接到固定地址，zig 的 `-Wl,-Ttext=` 不被支持，改用 `zig ld.lld --Ttext=`
  （`scripts/patch-musl.py`）
- musl 缺的几个 glibc 符号在 `scripts/musl-compat/` 里补：`sys/queue.h`、
  `rlimit64`、`statfs64`、`MSG_COPY`、`TEMP_FAILURE_RETRY`

产物：485KB（strip 后），`ELF 64-bit LSB executable, ARM aarch64, statically linked`。

## 四、验证

1. qemu `-strace` 确认启动路径无 `rseq`/`clone3`（0 次命中）
2. CI 冒烟测试改用"白名单模式"的 filter：**号 ≥ 400 一律 TRAP**（含 `-1`），
   再加 `rseq(293)`、`membarrier(283)` —— 这样上一版的写法会被当场抓住
3. 真机验证：装 build-23，看 `proot 自检 exit=0`

## 五、经验

- 见到 `128+31` 先想 seccomp，但**别假设未命中的 syscall 会返回 ENOSYS**；
  Android 是 TRAP。
- 改 syscall 号来"绕过"白名单是死路：任何不在名单里的号都一样被杀。
  要么让程序根本不调它（换 libc），要么在 seccomp 之前改（ptrace）。
- 模拟测试的 filter 必须模拟**真实策略的默认动作**，否则就是自欺欺人。
